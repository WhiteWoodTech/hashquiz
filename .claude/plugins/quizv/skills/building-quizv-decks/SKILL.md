# QuizV Deck Builder Skill

Create, plan, and generate QuizV quiz decks in the `decks/` directory.

## When to Use This Skill

Activate when the user requests:

- Creating a new quiz or quiz deck
- Planning quiz questions from source materials
- Generating `.quizv.md` quiz files
- Adding a new deck to the `decks/` directory
- Building a quiz from documents, notes, or web research

### Example Trigger Phrases

- "Create a quiz about Kubernetes"
- "Make a quiz deck on JavaScript fundamentals"
- "Plan a quiz from these course notes"
- "Generate quiz questions from this document"
- "Add a new deck about REST APIs"
- "Build a quiz for my training session"

### NOT This Skill

Do NOT activate for:

- Running or serving quizzes (`bun run ... dev`)
- Theme customization
- Parser or server code changes
- Quiz file syntax questions (point to format reference instead)

## Workflow

Three commands handle the deck lifecycle:

```text
1. /quizv:new   →  Scaffold deck structure
2. /quizv:plan  →  Plan quiz content
3. /quizv:create →  Generate quiz questions
```

### Workflow Options

| Scenario | Command | Output |
|----------|---------|--------|
| Start a new quiz from scratch | `/quizv:new [topic]` | Deck scaffold with frontmatter |
| Plan questions from sources | `/quizv:plan` | `plan.md` in deck directory |
| Generate quiz from plan | `/quizv:create` | Complete `index.quizv.md` |
| Quick quiz (skip scaffold) | `/quizv:new [topic]` then `/quizv:create` | Scaffold + quiz |

### Why Plan First?

- Plans capture target difficulty, question count, and topic coverage
- Review checkpoint before investing in question generation
- Plans ensure even coverage of source material
- Easier to iterate on structure than on finished questions

## Deck Structure

Each deck lives in `decks/<slug>/`:

```text
decks/
└── my-quiz-topic/
    ├── index.quizv.md    # Quiz file (frontmatter + questions)
    ├── assets/           # Images, covers
    │   └── .gitkeep
    └── sources/          # Source documents + quiz plan
        ├── plan.md       # Quiz plan (generated by /quizv:plan)
        └── .gitkeep
```

## Key Rules

1. **One question at a time** when gathering information from the user
2. **Always respect the `.quizv.md` format** — see format reference
3. **Language is set at scaffold time** and respected throughout plan and generation
4. **Every question must have exactly 4 choices** — no more, no less. This is a hard UI constraint
   (the player app renders a 2×2 grid). See [Choice Count Rule](#choice-count-rule) below.
5. **Each question must have at least 1 correct answer** (and at most 3, so there is always at least 1 distractor)
6. **`max-questions` and `max-time` are mutually exclusive** in quiz frontmatter
7. **Explanations are mandatory** — every question must have a blockquote explanation
8. **Timer values** should match difficulty: 15-20s easy, 20-25s medium, 25-35s hard
9. **Choices must look visually identical** (same formatting, length, grammar) so the correct
   answer doesn't stand out. See [Visual Homogeneity Rule](#visual-homogeneity-rule) below.

## Visual Homogeneity Rule

**Choices must look visually identical so the correct answer doesn't give itself away.** A common
generation mistake is to elaborate only on the correct option (extra detail, parenthetical hint,
bold emphasis…) while the distractors stay plain. Players spot the asymmetry, not the truth.

### Anti-patterns to avoid

| Anti-pattern | Example (bad) | Fix |
|--------------|---------------|-----|
| Only the correct answer has `**bold**` | `- [x] **HyperText Markup Language**` vs `- [ ] Hyper Transfer Markup Language` | Either bold all 4 or none |
| Only the correct answer has *italic* | same idea | same fix |
| Only the correct answer has `(parentheses)` with extra context | `- [x] Reasoning (raisonnement étendu interne)` vs `- [ ] Generative` | Parenthesise all 4 or none |
| Only the correct answer uses `` `backticks` `` | `- [x]` `roles/cloudsql.client` ` vs `- [ ] Owner role` | Backtick all 4 or none |
| Correct answer is noticeably longer or shorter | `- [x] A full sentence explaining…` vs three 2-word distractors | Match the verbosity across choices |
| Correct answer has trailing punctuation when others don't | `- [x] HyperText Markup Language.` | Drop the period everywhere |
| Different capitalisation / case style on the correct one | `- [x] OAuth 2.1` vs `- [ ] saml` | Apply the same style to every choice |
| Correct answer is the only one starting with a verb / proper noun | `- [x] Apply patches automatically` vs three short noun phrases | Rephrase so all 4 start the same way |

### Checklist before committing a question

- [ ] All 4 choices use the **same markdown formatting** (bold/italic/code spans on all or none)
- [ ] All 4 choices have **similar length** (within ~30%)
- [ ] All 4 choices follow the **same grammatical pattern** (same starter, same tense, same punctuation)
- [ ] Move any extra context (definitions, parenthetical hints) from the choice **into the `>` explanation block**

The right place to give pedagogical context is the explanation that appears AFTER reveal — not the
choice itself.

## Choice Count Rule

**Every question MUST have exactly 4 choices.** This is non-negotiable — the host and player UIs are
designed around a 2×2 answer grid, and questions with more or fewer options break the layout.

### How to fit a topic into 4 choices

| Situation | What to do |
|-----------|------------|
| You wrote 5+ options | Drop the weakest distractors (the most obviously wrong, or duplicates of a stronger one) |
| Topic has 5+ correct items | Pick the 3 best correct ones + 1 strong distractor, rephrase to "sélectionnez 3" / "select 3" |
| Topic has only 2-3 real options | Add 1-2 plausible distractors (common misconceptions, near-misses, fake-but-believable terms) |
| You want all-correct (no distractor) | Don't — always keep ≥1 wrong choice so the question stays a quiz, not a check-the-box list |

### Phrasing rule for multi-select

When the question asks "select N", `N` must be **strictly less than 4** (so there is always at least
one distractor). Use `sélectionnez 2` or `sélectionnez 3` — never `sélectionnez 4`.

### Validation

The CLI `check` command does **not** enforce this rule (the parser only requires ≥2 choices). You must
verify manually or with a one-liner:

```bash
awk '/^##[^#]/ { if (q) print q ": " n; q=$0; n=0 } /^- \[[ x]\]/ { n++ } END { if (q) print q ": " n }' \
  decks/<slug>/index.quizv.md | grep -v ": 4$"
```

This prints any question whose choice count differs from 4. Empty output = all good.
